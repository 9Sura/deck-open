# DECK

Free, AI-generated DECA practice: generated practice tests, a browsable bank of
16,283 questions, event vocabulary, daily roleplays, and progress / error-log
analytics.

**Not affiliated with DECA Inc.** DECA is a trademark of DECA Inc. Every piece of
practice material here is original and AI-generated; none of it is official DECA
content.

---

## What this is

Two halves that meet through committed data files:

- **`frontend/`** — the Next.js app students use.
- **`backend/`** — Python tools that *author* the study material offline and
  commit it into the app's `public/` tree.

**There is no runtime model compute in the app.** It never calls a model, never
needs an API key, and only ever reads data that is already in this repository.
That is why it runs from a clone with nothing configured.

```
deck-open/
├── frontend/                       # Next.js 16 app — this is what you run
│   ├── app/                        # routes: / , /test-generator , /question-bank , /vocab ,
│   │                               #   /roleplay , /progress , /review , plus static pages
│   │                               #   (/developers , /privacy , /terms , /changelog , /help)
│   ├── components/                 # UI: hand-drawn notebook look-primitives, ui/, page pieces
│   ├── hooks/                      # shared React hooks
│   ├── lib/                        # ProgressStore, route gating, themes, DECA mirrors
│   ├── public/question-bank/       # THE question bank — canonical, served verbatim (16,283 questions)
│   ├── public/vocab/               # event vocab catalogs (28 events, 1,400 terms)
│   ├── public/roleplays/           # roleplay bank + the dealt day files
│   ├── scripts/                    # derive-bank-artifacts.mjs, sync-vocab.mjs, check-data-sync.mjs
│   └── supabase/migrations/        # schema for the optional accounts feature
│
├── backend/                        # offline authoring tools — never runs in production
│   ├── test-gen-model/
│   │   ├── src/                    # practice-exam pipeline: generators/ + prompts/
│   │   └── data/                   # NOT published — real DECA exams + PI library (see its README)
│   ├── roleplay-gen-model/
│   │   ├── src/                    # fill_bank.py (authoring driver), icdc_gate.py (quality bar), prompts/
│   │   └── data/                   # NOT published — real DECA roleplays + PI library (see its README)
│   └── feat-vocab/                 # vocab catalog + source data, synced into public/vocab/
```

## Quickstart

**Prerequisites:** [Node.js](https://nodejs.org) 20+ and npm. No Python, no keys,
no database.

```bash
cd frontend
npm install
npm run derive-bank     # builds lib/data/pi-inventory.json from the question bank
npm run dev
```

Open **http://localhost:3000**.

`npm run derive-bank` is required once after cloning, and again after any change
to the question bank. It scans `public/question-bank/` and writes the derived
artifacts `lib/` imports at build time. One of them — `pi-inventory.json` — is
generated rather than committed on purpose; see [What is not
here](#what-is-not-here).

Other scripts:

```bash
npm run build          # production build
npm run lint           # eslint
npm run check-data     # READ-ONLY: are the derived artifacts stale / is vocab behind?
npm run sync-vocab     # WRITES public/vocab/ from backend/feat-vocab/data/
```

**There is no test runner and no test suite.** Verification means running the app
or running a generator's own verify/gate tool.

## Accounts are optional

Signed out, the app uses a non-logging store: writes are dropped, reads come back
empty. Every practice feature works — test generator, question bank, vocab,
roleplays — but nothing is recorded, so `/progress` and `/review` are hidden.

Signing in swaps in a syncing store (IndexedDB-first, with a durable outbox
flushing to Supabase). To run that half yourself you need your own Supabase
project:

```bash
cp .env.local.example .env.local     # then fill in your project's URL + anon key
```

Apply `supabase/migrations/` to that project. Auth is username + password with no
email step — usernames map to synthetic internal addresses. With
`NEXT_PUBLIC_SUPABASE_*` unset the app stays in guest mode and no auth UI appears
at all.

## What is not here

Three deliberate omissions. None of them is a missing file to be filed as a bug.

**1. The generators' input corpus.** `backend/*/data/` is empty except for a
README explaining it. It holds real past DECA exams and roleplays — copyrighted
material used as few-shot examples during authoring — plus a reproduction of the
performance-indicator taxonomy authored by MBA Research. None of that is ours to
redistribute. Every prompt, validation gate and generator that consumed it *is*
published, along with its complete output. The pipelines are readable here, not
runnable.

**2. `lib/data/pi-inventory.json`.** Generated by `npm run derive-bank` from the
question bank rather than committed. A file that *is* the DECA performance-
indicator taxonomy is a liftable copy of someone else's curation; the same PI
names attached as tags to 16,283 original questions are not. Deriving it locally
keeps the app identical and keeps that file out of the repository.

**3. Internal planning.** Campaign plans, run summaries, generator output logs
and project history stay in the private working repo. They are development
bookkeeping, not something a reader of this repository needs.

## A note on the practice material

Every question, explanation, vocabulary entry and roleplay in this repository was
generated by a language model and reviewed by automated gates — not by DECA, and
not by a teacher. It is study material, not an answer key. Treat a disagreement
between this bank and your competition guide as the guide being right.
